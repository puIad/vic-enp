## 2026-10-22: the strict catch

Settled with the owner in a grilling session after they tried the live build on laptops and phones: the catch
worked only sometimes, seemed to start working only after a first pass through the page, and on phones caught a
fling, then let it go as the phone kept coasting. Why, from the code (Claude): the phone catch glided back while the
browser's own momentum ran on under it (script can't stop native momentum, so 83's "the momentum stops" never held),
and the glide had already closed that fling, so nothing caught it again; every catch was gated on speed, so ordinary
scrolling crossed; and each formation is built the first time its cut is reached (`World.tsx`), so first-pass stalls
skewed the speeds the catch read. The answer: decide from the input, before the page moves. The spec is in
[experience.md](experience.md#the-catch).
